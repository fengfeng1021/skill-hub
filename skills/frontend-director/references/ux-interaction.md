# UX 與互動基線

把每個主要流程寫成狀態與事件，不要只檢查靜態畫面。

## 狀態模型

對每個可互動功能列出：

```text
初始 → 載入 → 成功
          ├→ 空白
          └→ 錯誤 → 重試／恢復
```

再補充 disabled、取消、中斷、重入、逾時、離線和權限不足中適用的狀態。

## 互動檢查

1. 每個動作都有立即且可理解的回饋；長操作顯示進度或可取消狀態。
2. 錯誤靠近原因，說明下一步；不得只顯示錯誤碼或無法恢復的 toast。
3. Modal、menu、popover 和 drawer 正確管理初始焦點、焦點限制、Escape、外部關閉及焦點返回。
4. 鍵盤能完成與指標相同的核心任務；焦點順序符合視覺和語意順序。
5. 按鈕、連結、切換、slider 和輸入欄位使用正確語意及名稱。
6. Undo、確認和危險操作的摩擦程度與影響相稱。
7. 返回、重新整理、深連結和瀏覽器歷史不會讓使用者丟失必要狀態。
8. 視覺回饋必須可感知；不能只讓數值在背景改變而畫面看不出進度。

## 驗證

UX 規劃 Gate 先輸出主要流程模型、錯誤／空白／恢復方案與鍵盤／焦點／觸控計畫。實作完成後再於 integration Gate 用真實瀏覽器走完主要、替代、錯誤與恢復路徑，至少驗證鍵盤、焦點返回、觸控尺寸和窄螢幕。規劃不能代替互動實測；修正 UX 若改變版面或元件責任，回到 UI Gate 重驗。
