# 風險導向安全交付

每個前端任務至少執行基線檢查；高風險變更需要專門安全能力。外部安全 skill 是增強，不得用來省略基本資料流推理。

## 分級

| 風險 | 典型變更 | 最低要求 |
|---|---|---|
| 高 | 認證、授權、支付、個資、檔案上傳、不可信 HTML、外部命令 | 威脅建模、專門審查、重現、修補與完整重驗 |
| 中 | API 寫入、第三方整合、持久化、SSR、敏感設定 | 資料流、權限、注入、秘密、依賴與錯誤洩漏審查 |
| 低 | 靜態內容、樣式、非敏感互動 | 秘密、DOM XSS、外部資源、危險 URL 與依賴差異檢查 |

## 前端基線

- 不把密鑰、token 或私人端點放進用戶端 bundle、日誌或截圖。
- 不以隱藏按鈕或前端路由保護代替伺服器授權。
- 不可信內容不得直接進入 HTML、URL、CSS 或命令上下文；使用對應安全 API 和 allowlist。
- 驗證 redirect、download、postMessage、localStorage、cookie、第三方 script 和跨來源資料邊界。
- 錯誤訊息不洩漏憑證、個資、內部路徑或堆疊；記錄功能也遵守同一限制。
- 新增相依要檢查必要性、來源、版本、lockfile 差異與已知風險。
- 安全控制需有負向測試，不只驗證正常流程。

## 交付門檻

Critical／High 必須修正並重驗。Medium 要有已驗證緩解措施，否則需使用者明確接受風險。Low 可帶影響說明交付。高風險任務缺少威脅建模或專門審查能力時，不得宣稱 production-ready。

任何安全修補都會讓受影響的任務與整合證據失效，必須回到 Coding Loop。
