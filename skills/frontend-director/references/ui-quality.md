# UI 階段調度基線（調度層 — 不承載設計禁令）

UI 的視覺標準分工：`impeccable`（craft 與大膽導向）＋ `ui-ux-pro-max`（模式資料庫）為一般創意專案的默認組合；`taste`（品味逆向）僅在使用者提供參考網站時載入；`hue`（設計語言生成）僅在使用者要求模仿特定品牌或建立可重用設計語言時載入。本檔案只規定 ui 階段「必須存在哪些工作與證據」供 Gate 驗證，不規定「設計不得做什麼」。具體的風格建議（如「避免漸層 hero」）屬於子 skill 的參考內容，不是本階段的檢查。

## ui 階段必做（Gate 驗證項目）

1. **創意等級判定**：依 [creative-tier.md](creative-tier.md) 記錄 Tier（Tier 3 必填判定理由）。
2. **設計方向文件**：氣質描述（有判別力的詞）、採用與避免的參考方向、設計 tokens（色彩／字型／間距／動效節奏）。方向文件存在且可回扣需求即可通過調度 Gate；「夠不夠好」由子 skill 與 tier 標準裁決。
3. **Signature visual 計畫**：列出承載產品識別或事實主張的簽章視覺，各自記錄 claim、truth mode（事實性畫面只能 `sourced`／`procedural-validated`，見 visual-truth.md）、來源或模型、渲染狀態（桌面／手機／細節）。Tier ≥2 另記錄 signature-moment-plan（SM-1..SM-4 之一）。
4. **雙尺寸規格**：主要元件在桌面（≥1024）與手機（320–414）的版面行為與狀態（正常／錯誤／空白／載入／reduce-motion）。
5. **bolder 對照（Tier 3）**：與 3 個同類頂尖站書面比較，記錄「我們比它多做了什麼」；無超越點回設計階段。

## 本檔案不包含
- 「不要漸層 hero／不要三張功能卡／不要玻璃擬態」類別禁令（屬於子 skill 的參考語彙）。
- 「動效只用於引導注意」類克制語義（見 motion.md 的調度層版本）。
- 對視覺風格的合規性裁決（由 tier 與子 skill 標準決定）。

## 品質底線（不變，但僅限於可用性）
- 文字層級、閱讀寬度、對比、焦點、觸控目標可用。
- 320–375px 無水平溢出；1440px 拉寬不失結構。
- 內容增長、翻譯、慢網路與圖片失敗不破壞主要流程。
- 圖示有語意；互動控件用正確元素。
- 上述為可用性底線，通過不等於設計完成；設計完成標準依 tier 與子 skill。
